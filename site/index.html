What it does

A checkup for the machine you actually work on.

Two problems, one tool: the disk that keeps filling up, and the RAM that keeps running out. DevDoctor measures both, explains what it found, and only acts with your sign-off.

Disk cache analysis

One command surfaces every known cache — Docker layers, model weights, build artifacts, virtualenvs — sized accurately with symlink-safe, hard-link-deduped walks. Sorted biggest first.

Memory advisor

See live memory pressure and the top consumers — browsers, Electron apps, Docker, local LLM runners — with one-click actions to quit the app or stop the container that's swapping your machine to a crawl.

Preview-first by design

clean defaults to a dry run: zero prompts, zero shell commands. Every entry is labelled safe, reclaimable, or dangerous — and dangerous ones are skipped unless you opt in.

Snapshots & diff

Snapshot usage before a cleanup, then diff two points in time — or against live — to see exactly what each cache reclaimed and how your disk trends over weeks.

CLI & web today, desktop soon

Rich terminal tables with JSON output for scripting and a local web dashboard with a live cleanup wizard — both shipping now, with a hardened desktop app on the way. Same engine underneath.

100% local & private

No telemetry, no accounts, no network calls. The web UI binds to loopback only, guarded against DNS-rebinding, and commands run as argv lists — never through a shell.

Disk, measured

The safety model

A cleanup tool you can actually trust with rm -rf.

Destructive tools earn trust by refusing to be reckless. DevDoctor is built so the dangerous path is always the deliberate one.

Preview is the default

clean shows what it would remove and stops. No prompts, no shell calls. You opt into action with --execute, then confirm each entry and a final summary.

Recipes are reviewable

recipe writes a shell script with every destructive line commented out. Read it, uncomment what you want, run it yourself. No surprises hidden in an abstraction.

No shell, ever

Commands execute as argv lists — never through a shell — with every path safely quoted. A filename with a quote or $(…) in it is inert data, not an injection.

Two ways in today, a third on the way

Live in the terminal, or don't. Same engine.

A single Python core drives every surface, so a scan means the same thing whether you typed it or clicked it. The CLI and web UI ship today; the desktop app is in progress.

Where it earns its keep

The recurring "why is my disk full again?"

AI / ML developers

Reclaim the model-weight sprawl

Hugging Face, Ollama, and LM Studio each keep their own multi-gigabyte copies. DevDoctor sums the true cost across all three — including the HF cache LM Studio points into — so you can clear what you're not using.

Before a big build or update

Free space on demand

Out of room mid-compile or ahead of an OS update? One scan, sort by size, clean the safe and reclaimable entries, and watch the free-space number climb — with a snapshot to prove what it recovered.

When the fans won't stop

Track down the memory hog

The memory advisor ranks live consumers by real RSS and flags the pressure state, then offers to quit the app or stop the container — the safe fix, not a guessed kill.

Anyone who likes receipts

Watch disk usage trend

Auto-snapshots capture usage over time. Diff any two points — or against live — to see which caches keep growing back and decide what deserves a permanent spot on your ignore list.

Get started

Installed and scanning in under a minute.

Requires Python 3.12+ on macOS or Linux. Install with uv and you're diagnosing immediately.

$ uv tool install git+https://github.com/katagun/devdoctor
$ uv tool install "diskdoctor[web] @ git+https://github.com/katagun/devdoctor"
first run
# see everything, biggest first
$ diskdoctor scan
 
# preview a cleanup — nothing is deleted
$ diskdoctor clean
 
# interactive cleanup, safe entries auto-approved
$ diskdoctor clean --execute --yes-safe
 
# open the local dashboard (web extra)
$ diskdoctor serve
